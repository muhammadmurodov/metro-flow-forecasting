# 90-day read-only pilot concept

This describes a possible future trial with a metro operator. This package uses only the bundled Hangzhou dataset.

1. **Days 1–15:** approve purpose, data-sharing, minimal 15-minute entry/exit aggregates, security, retention and evaluation criteria.
2. **Days 16–40:** train with operator-authorized data; evaluate chronological holdouts, busy station errors, seasonal baselines and prediction intervals.
3. **Days 41–70:** run forecasts in **shadow mode** for operator review, without controlling trains, gates or staffing.
4. **Days 71–90:** assess error, lead time, false alarms, usability and cost, with documented go/no-go decision.

Proposed input: aggregated entry/exit counts, stable station IDs, time zone, schedule/calendar, disruption flags. No personal card records required. Targets and alert thresholds must be negotiated with operators; this project's research metrics are not deployment promises.
